# Промпт: собрать мод «реакции на сообщения» для Claude Code

Скопируй текст ниже в Claude Code (2.1.287 или новее, десктоп или терминал). Агент соберёт мод с нуля и проверит его. Готовая реализация лежит рядом, в папке `reactions/`.

---

Собери мне мод для Claude Code (Claude Code Mods: плагин с модулем хуков) — реакции на сообщения, как в мессенджере. Сначала загрузи скилл `plugin-authoring` и сверяйся с его типами (`claude-code.d.ts`) и `reference.md`, а не с памятью: API модов новый.

## Что должно получиться

**Я реагирую на сообщения Claude**
- На любое сообщение Claude, включая промежуточные тексты между вызовами инструментов, можно поставить одну из реакций: 👍 👎 🤔 😂 ❤️ 🔥.
- В правом нижнем углу сообщения бледный ☺. При наведении курсора на сообщение рядом с ☺ раскрывается ряд реакций, клик по ☺ открывает ряд и без наведения.
- Выбранная реакция стоит под сообщением, вокруг неё полсекунды разлетаются цветные пиксельные искры (■ ▪ ·). Повторный клик по реакции её снимает. Случайный двойной клик (меньше 400 мс) не должен ставить и тут же снимать реакцию.
- Само сообщение рисует приложение. Мод оборачивает его родную отрисовку и добавляет только своё. Сводки между шагами (`isSummary`) и пустые блоки не трогать.

**Claude получает реакцию, не прерываясь**
- Если Claude работает, реакция приходит ему скрытым контекстом вместе с результатом его следующего вызова инструмента. Если он стоит — вместе с моим следующим сообщением. Отдельного хода реакция не запускает.
- В заметке для Claude указаны реакция и начало сообщения, а также значение реакций из этой пачки: 👍 — продолжай так же; 👎 — остановись, в двух словах скажи, что делаешь, и спроси, как нужно; 🤔 — перепроверь шаг; остальные — эмоция. Если в пачке нет 👎 — «отдельно на реакции не отвечай».
- Реакция доставляется ровно один раз. Если вызов инструмента отклонён или моё сообщение не дошло, реакция ждёт следующего раза. Вызовы субагентов и других плагинов её не забирают.

**Claude реагирует на мои сообщения**
- Метки на моих сообщениях: 👀, когда Claude его прочитал; ✅ в конце хода; ⏹️, если ход остановили; ⚠️ при ошибке. Сообщение, отправленное посреди работы, получает 👀 в момент, когда Claude его подхватил.
- Инструмент `react` (одно эмодзи), которым Claude ставит свою реакцию на моё последнее прочитанное сообщение. Только основной агент, только эмодзи без слов. В описании инструмента попроси ставить реакции живо: 😂 на шутку, ❤️ на тёплые слова, 👍 на согласие, 🤝, 🙏, 🔥.
- Метка и реакция Claude дописываются последней строкой в мой пузырь. Два одинаковых сообщения («гуд», «гуд») держат каждое свои метки.

**Сохранность**
- Реакции, метки и ещё не доставленные реакции переживают перезапуск приложения: хранить в `$.store` по id чата, держать последние 30 чатов. После перезапуска незаконченное 👀 превращается в ⏹️.
- Каждое сообщение — свой член `StateFamily`: изменение перерисовывает только его, а не всю ленту.

## Подводные камни (проверено на 2.1.293)

- Аргументы инструмента, зарегистрированного через `$.tool.register`, приходят в хук `tool.call` прямо на событии (`e.emoji`), а не в `e.input`.
- Доставка во время работы: в общем хуке `tool.call` сначала `const ran = await next(e)`, затем, если `ran.deny === undefined`, `next.origin.plugin === 'engine'` и нет `e.agentId`, вернуть `{ ...ran, context: [...(ran.context ?? []), заметка] }`.
- Сообщение, набранное посреди хода, приходит в `prompt.submit` с `e.turnId` и стоит в очереди. Claude его подхватывает, когда в `session.append` приходит строка `type: 'attachment'`, `name: 'queued_command'`. Если ход кончился раньше, сообщение начинает следующий ход и приходит в `turn.start`.
- В десктопе `requestId` пузыря моего сообщения (`UserMessage`) равен `uuid` строки транскрипта из `session.append` с `door: 'prompt'`. По нему и надо вешать метки, а запасной ключ — хэш текста.
- Родную отрисовку оборачивать так: `const own = await next(e)`, затем `<Box key={...}>{own}…</Box>`. Box с `key` — область наведения.
- Раскрытие по наведению: `display: 'none'` плюс `hover: { display: 'flex' }`. Если ряд уже открыт кликом (`display: 'flex'`), `hover` не передавать, иначе движок отвергнет дерево: «this Box is already shown». Абсолютно позиционированные элементы держать внутри рамки сообщения (`bottom: 0, right: 0`), за краем их может обрезать.
- Валидатор (`claude plugin validate`) должен видеть каждую ссылку на состояние: `memberOf(family, { requestId: id })` писать прямо в месте вызова, не прятать в свою функцию. Файл контракта `types/index.d.ts` — без `import` и без невидимых символов: эмодзи вроде ⏹️ и ⚠️ содержат вариационный селектор, в комментарии контракта их нельзя.
- Рендер-хуки ничего не пишут в состояние. Писать можно из обработчиков нажатий и других событий через `update`.
- Ошибки логировать в `$.ui.log(…, { to: 'debug' })`. Сбой хранилища не должен останавливать ни сообщение, ни вызов инструмента.

## Проверка

1. `claude plugin validate <папка мода>` и `tsc -p <папка мода>` — без ошибок.
2. Тесты на `claude-code/testing` (`claude plugin test <папка>`), поверхности `terminal` и `desktop`. Тестовому стенду нужны свои «низы»: `ui.render` для обоих компонентов, `ui.log` (вернуть `{ value: undefined }`), `store.*`, `session.id`. После событий движка вызывать `redraw()` у пузыря. Проверить: доставку реакции с ближайшим инструментом и ровно один раз; реакцию между ходами; снятие; двойной клик; сводки без изменений; 👀 → ✅ и реакцию Claude; два одинаковых сообщения; сообщение посреди хода; сообщение на стыке ходов; вызов субагента и отклонённый вызов; недошедшее сообщение; отказ `react` для слов и субагента; восстановление после перезапуска; смену чата в том же процессе.
3. Живая проверка в десктопе: наведение, клик, искры, реакция на промежуточное сообщение во время работы Claude, метки на своём сообщении.
